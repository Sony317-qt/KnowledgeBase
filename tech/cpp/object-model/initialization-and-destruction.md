## 一句话

构造按基类和成员声明顺序完成，异常只清理已构造完成的部分。

## 机制
- 没有虚继承时：基类按继承声明顺序、成员按类内声明顺序初始化，最后执行构造函数体。虚基类由最派生类先初始化。
- 初始化列表决定用什么初始化，不决定成员先后。a 声明在 b 前时，b(10),a(b) 仍先初始化 a，会读取未初始化的 b；不保证编译报错。
- 析构先执行本类析构函数体，再逆序销毁成员、直接基类；虚基类最后销毁。
- 构造函数抛异常：本对象构造未完成，不调用本对象析构；已完成的成员、基类按逆序清理。基类构造失败时同理，派生类成员尚未开始构造。
- 异常先 throw，找到匹配处理器并栈展开清理，最后进入 catch。
- 派生类初始化列表 Base(10) 明确选择基类构造；省略通常调用默认构造。函数体中的 Base(10) 只是临时对象。
- explicit 阻止构造函数参与相应的隐式转换，Number n(10)、n{10} 仍可用；n=10 不可。
- T x(args) 是直接初始化，T x{args} 是直接列表初始化；T x=expr 为拷贝初始化，不保证发生实际复制。花括号禁止窄化，但可能影响构造函数选择。

## 追问链
1. 初始化列表写 b 在前，会先构造 b？→ 不会。
2. b 构造失败，a 已成功，catch 前谁析构？→ a 先清理，b 和整体不执行自身析构。
3. 析构函数体能访问成员？→ 可以，成员此时尚未销毁。

## 补充：析构与安全释放（2026-11-02）

- 析构函数可以在内部捕获、处理异常，通常不应让异常逃出。析构通常隐式为 noexcept(true)；基类或成员析构可能抛异常时，隐式异常说明可能不同。
- noexcept 不会自动捕获异常，而是承诺异常不逃出；违反时调用 std::terminate，外层 catch 不能挽救。即使声明 noexcept(false)，在另一个异常的栈展开期间，析构再让异常逃出仍会终止程序。
- 清理可能失败时，析构内部处理并使用不抛异常的方式记录；需要调用者处理失败的操作，提供显式 close/save 接口，析构负责兜底。不把吞掉错误作为通用方案。
- new T 配 delete，new T[n] 配 delete[]；即使 n=1 或 T=int 也不能混用。正确的 delete[] 销毁各元素后释放空间；混用是未定义行为，不保证“只析构第一个”、一定崩溃或抛异常。
- 通过 Base* 删除 Derived 对象，基类应有虚析构，先执行 Derived 析构，再执行 Base 析构。基类析构非虚时这样删除属于未定义行为；其他虚函数不会自动使析构变虚。直接通过 Derived* 删除不需要靠虚分派定位析构。

### 本轮追问与易错点

1. noexcept 用来避免 terminate？→ 相反，它承诺异常不逃出，违反就 terminate；try/catch 才负责捕获。移动操作确实不抛异常时通常标 noexcept，便于 vector 扩容选择移动。
2. 数组错用 delete 一定只析构第一个？→ 不保证；两种释放错配都属于未定义行为。
3. 为什么需要虚析构？→ 基类指针的静态类型不同于实际对象类型，虚析构保证完整派生对象被正确销毁；不能只理解为避免资源泄漏。
