# 2026-11-20 · 请求报文不带尖括号，但代码里两种分隔符都出现过

## 症状

最初理解：PLC 命令长这样——

```
<RUNSTEP,1,1;>
```

按这个前缀去日志里搜，搜不到；自己拼报文发出去，PLC 也不认。

## 定位

读 `PDUMotionWrapper` 的发送与解析两侧：

- **发送侧**：`CHK,1;`、`SETPOS,1,3,12.500;`、`INTERVAL,1,14,0.040,1,1;` —— **无尖括号，逗号分隔**。
- **接收侧**：`CHK,1,0011,12.345;`、`CMD,1,1;` —— 状态字段是**十六进制**，`1` = Success，`2` = Failure。
- 解析里同时容错了**空格分隔**的写法（历史遗留或不同 PLC 固件）。

## 根因

- 记忆把"接收时容错尖括号/空格"记成了"发送要带尖括号"。
- 代码里两种分隔符写法都存在（逗号与空格），**发送只认逗号，接收时容错空格**。

## 修法 / 教训

- **看报文语法必须分发送侧和接收侧**分别确认，不能靠一处代码推断另一处。
- 状态字段是十六进制，用十进制读会得出完全不同的状态（例如 `0011` 是 17，不是 11）。
- 同类认知修正还有：处理完的图像传给**上位机**而不是 PLC；上位机**不下发图片**，只下发命令与参数。
