# 技术知识库

纯 markdown + git。没有数据库、没有后端：**目录树就是索引，`[[双链]]` 就是外键**，`rg` 就是搜索引擎。

---

## 一、为什么这样组织

1. **技术点与项目是一张图，不是两棵树。**
   项目是"这些技术点在真实约束下怎么组合"的证据；技术点是"可复用的知识原子"。两者用 `[[...]]` 相连，答案永远是双向可查的。
2. **一个文件 = 一个知识原子。**
   大文档只会在"要复习"时被打开；原子文件才能在写代码、被追问、修 bug 的瞬间被链接进去。
3. **只在三种时刻写**：被追问到答不出 / 踩了坑 / 读到关键段落。**不预先建空目录。**
4. **每条必须有"追问链"和"项目证据"。** 这是它区别于网上笔记的唯一理由。

## 二、目录

```
KnowledgeBase/
├── README.md                 # 本文件：约定与流程
├── meta/
│   ├── index.md              # 仪表盘：有哪些点、该复习什么、本周待补
│   ├── plan-*.md             # 阶段计划（如面试冲刺）
│   └── templates/            # 三个模板，新建文件从这里复制
├── tech/                     # 技术点，按语言/领域分层
│   └── cpp/
│       ├── object-model/
│       ├── memory/
│       └── concurrency/
└── projects/                 # 项目，一个目录一个项目
    └── industrial-vision-measure/
        ├── README.md         # 一页纸：电梯陈述 + 架构 + 我的职责
        ├── decisions/        # ADR：关键决策为什么这么定
        └── incidents/        # 踩坑记录：症状 → 定位 → 根因 → 修法
```

## 三、命名与 ID

| 对象 | 规则 | 例 |
|---|---|---|
| 技术点 ID | 路径去掉 `tech/` 与 `.md` | `cpp/object-model/virtual-dispatch` |
| 文件名 | 全小写、中划线、动词优先 | `virtual-dispatch.md`（不是 `CppVirtual.md`） |
| 项目 ID | 目录名 | `industrial-vision-measure` |
| ADR | `NNNN-短标题.md` | `0001-threading-model.md` |
| 事故 | `YYYY-MM-DD-短标题.md` | `2026-10-29-frame-tearing.md` |

## 四、frontmatter 规范

```yaml
---
id: cpp/object-model/virtual-dispatch
title: 虚函数分派
level: 3
tags: [cpp, oop, interview]
aliases: [动态绑定, vtable, 虚表]
reviewed: 2026-10-29
next_review: 2026-11-02
projects: [industrial-vision-measure]
sources: [cppreference, Effective C++ Item 7]
---
```

### level 的定义（唯一进度指标）

| level | 含义 | 判定方式 |
|---|---|---|
| 0 | 听过，说不清 | 看到词有印象 |
| 1 | 能复述定义 | 合上笔记能说出"是什么" |
| 2 | 能讲机制 | 能说清"怎么实现的、代价是什么" |
| 3 | 能扛追问 | 连续追问 3 层不倒 |
| 4 | 有实战证据 | 能给出项目里的具体取舍和数字 |
| 5 | 能教人 | 能给人讲明白并回答反驳 |

> 没有项目证据的知识点，**最高只标 2**。这条规则逼你把知识和经历绑定。

## 五、一条技术点笔记的写法

四段，总长 **300–500 字**（超了就是抄书）：

1. `## 一句话` —— 一条能被背下来的结论
2. `## 机制` —— 3–6 个要点，说清"怎么实现的"
3. `## 追问链` —— 面试官会往哪打，第 1/2/3 层各是什么
4. `## 项目证据 / 反例` —— 我在哪用过、踩过什么；以及"常见错误说法"

**`## 追问链` 是全库最值钱的一段。**

## 六、每周复习流程（15 分钟）

1. **筛**：`level <= 2` 或 `next_review <= 今天` 的条目（看 `meta/index.md`）
2. **合上笔记**，口头重写"一句话"和"追问链"
3. **更新** `reviewed` / `next_review` / `level`
   间隔按 2 → 4 → 8 → 16 天递增；讲不出来就退回 level 1，间隔回到 2 天

---

## 七、每月链接体检

- **孤儿文件**：没有任何笔记链接它 → 合并或删
- **枢纽点**：被链接最多的 3 个 → 这是你的强项，面试时主动往上引
- **重复**：同一概念两个文件 → 合并，保留一个 ID，另一个放 alias

> 积累不是"文件变多"，是**链接变密、level 变高**。

## 八、git

```bash
git add -A
git commit -m "cpp: add virtual-dispatch (level 2)"
```

一次提交对应一个知识动作。历史本身就是"我怎么想过来的"。

## 九、不要做

- ❌ 按书的章节建目录（第 1 章 / 第 2 章）

- ❌ 抄教程（"RAII 的优点有 1234"）—— 网上有，不需要你写
- ❌ 一次建 200 个空文件
