# 维护流程（怎么操作）

> `README.md` 讲"为什么这样组织"，本文件讲"每次具体怎么做"。
> 两者冲突时，先按本文件执行，再回头改 README。起点：2026-10-29。

## 一、分工

| | 你 | 我 |
|---|---|---|
| 身份 | 唯一的知识来源 | 仓库管理员 / 编辑 / 反方提问者 |
| 做 | 口述、贴代码、报数字、判断对错 | 按模板写、维护 index 与双链、体检、扮演面试官 |
| 不做 | 不用管格式和链接 | 不替你编项目证据，不替你抬 level |

两条铁律：

1. **没有你的口述，我不写"项目证据"。** 缺数字就写 `TODO(数字)` 并进待补队列，不编。
2. **没有你的确认，我不改 level。** 我只给"建议 level + 理由"。

## 二、一个知识动作从哪来

| 入口 | 触发 | 落到哪 | 谁先动 |
|---|---|---|---|
| 被问住 | 模拟面 / 真实面试里答不出 | `projects/<p>/incidents/` 或技术点的"追问链" | 我记录，你补"应该怎么答" |
| 踩坑 | 调试 / 线上出问题 | `projects/<p>/incidents/YYYY-MM-DD-*.md` | 我先问五问，你再答 |
| 读到关键段 | 书 / 文档 / 源码 | `tech/...` 原子笔记 | 你给出处或原文，我不凭印象写 |
| 随口"记一下" | 对话里冒出来的点 | 我判定属于上面哪一类 | 我判定，你确认 |

### 踩坑五问（固定问法）

1. 症状是什么，谁先发现的？
2. 时间线：什么时候好的、什么时候坏的，中间改了什么？
3. 复现条件：必现还是偶发？换机器 / 换数据还复现吗？
4. 你当时以为是什么？为什么？
5. 最后怎么定位、怎么修的？

> 第 4 问最值钱：它记的是**错误的直觉**，比正确答案更能防复发。

## 三、单次会话（15–25 分钟）

1. **开场 1 分钟**：我读 `meta/index.md`，报出 `next_review <= 今天` 的条目和待补队列。
2. **复习 5 分钟**：你合上笔记口述"一句话 + 追问链"；我按三层追问，只记"通过 / 卡在第几层"，不替你圆场。
3. **写作 15 分钟**：**只碰一个文件**——一个新点，或一个旧口子。
4. **收尾 2 分钟**：过下面五项自检，同步 index，给一句提交信息。

### 收尾自检（五项）

- [ ] frontmatter 四个必填：`id` / `level` / `reviewed` / `next_review`
- [ ] `id` 与路径一致（路径去掉 `tech/` 和 `.md`）
- [ ] 所有 `[[...]]` 指向真实存在的文件
- [ ] level 有口述证据，没为好看而抬
- [ ] `meta/index.md` 的队列、统计、待补已同步

## 四、level 怎么给

| 我看到的证据 | 建议 |
|---|---|
| 看到词有印象 | 0–1 |
| 合上笔记能说"是什么" | 2 |
| 能说机制和代价，追问链第 2 层不倒 | 3 |
| 能报出项目里具体的数、具体的取舍 | 4 |
| 能讲明白并接住反驳 | 5 |

- 没有项目证据的条目，**最高只标 2**（README 的硬规则）。
- 讲不出来就退回 1，复习间隔回到 2 天。
- 一次会话里 level 最多动一级；要跳级，得连续两次口述都过。

## 五、间隔与队列

- 间隔按 `2 → 4 → 8 → 16` 天递增，我负责算 `next_review`。
- 超过 16 天不再排进周队列，进"冷冻"，只在月末体检里出现。
- `meta/index.md` 第一节按 `next_review` 升序；过期的标"已过期"而不是"待复习"。

## 六、每周 / 每月

| 周期 | 时长 | 做什么 | 产出 |
|---|---|---|---|
| 每周一 | 15 分钟 | 会话的第 1–2 步 | 一张本周复习队列 |
| 每月末 | 30 分钟 | 孤儿文件；被链最多的 3 个；重复概念；**计划里的空链接清单** | 合并 / 删除 / 更新 index 的"强项" |

> "计划里的空链接"指 index 待补、ADR 待办、README 的 TODO——它们不是资产，是欠账。每月清一次，欠账不会滚成山。

## 七、提交（本阶段暂停）

- 规矩仍然是**一个知识动作一个 commit**，消息形如：
  `cpp: add condition-variable (level 2)`、`project: 补帧率与节拍数字`、`meta: 增补 workflow`
- **2026-10-29 决定：暂不提交。** 收尾时我仍给出建议的提交信息，你记着或忽略；等恢复提交能力后按这些消息逐条补交，历史仍然成立。
- 恢复提交后，提交前额外查一项：`git status` 里没有意外的临时文件。

## 八、不做什么

- 一次会话写第二个技术点（README：不要一次建 200 个空文件）。
- 为了统计好看抬 level。
- 替你把"没答好"润色成"答得好"——incident 的价值就在原文。

## 九、阶段计划

- 阶段计划是临时文件：`meta/plan-YYYY-MM-DD-<主题>.md`，**阶段一结束就删**，不要留成常驻文档。
- 2026-10-29 那版 C++ 面试冲刺计划已随清空一并删除；当时排期的理由（`condition-variable` → `zero-copy` → 项目量化 → 视频链路）仍可参考 `meta/index.md` 的待补顺序。
- 要重新排期，从待补队列起手，新建一个 plan，而不是在旧文件上续写。
